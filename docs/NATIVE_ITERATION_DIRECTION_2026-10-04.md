## 1. 产品方向

继续使用 C# / .NET 10 / WPF。把灵屿做成有统一视觉语言的桌面活动入口：音乐、专注、提醒、文件和 AI 共享一个小岛，复杂编辑进入工作台。

优先完成“看起来一致、切换自然、状态可靠”的三个样板：音乐展开态、专注态、AI 工作台。随后补齐日常任务闭环。系统控制和外部 Agent 接入按模块增加，避免每增加一个功能就改动全部窗口。

这次以用户最新提供的七张图为视觉依据。图片中的应用表面、层级与互动关系进入客户端；岩石、笔记本、景深和官网大标题用于后续宣传。图片中的版本号、日期、地点、曲名、能力描述不是现有产品事实。不同图片的标志不一致，客户端继续使用现有统一的胶囊轮廓标志。

研究覆盖 30 个候选仓库，含衍生仓库和仅供设计观察的资料；不是声称穷尽所有开源项目。证据分级、固定版本与功能来源见 `docs/OPEN_SOURCE_ISLAND_MAP_2026-10-04.md`。灵屿与 eIsland 的原有来源说明继续保留。

### 3.1 材质与组件

下面是设计起点，需在 WPF 实窗校准，不是从宣传图片测得的精确像素。

| 项目 | 规格起点 |
|---|---|
| 主表面 | `#090A0D` 到 `#14161B` 的轻微纵向明暗；保持近黑 |
| 普通内容面 | `#15161B`；抬升控件约 `#22232B` |
| 主文字/次文字 | 沿用 `#F5F5F7` / `#A1A1AF`；低对比文字只用于非关键元信息 |
| 强调色 | 沿用 `#C3AAFF`，集中于进度、选中、焦点和状态 |
| 边缘 | 约 1 DIP 银灰渐变描边，上缘明、侧缘弱；检查分数 DPI 下的实际像素 |
| 图标 | 沿用矢量图标；常用尺寸 18–20 DIP，主动作 22–24 DIP；命中区至少 40×40 DIP |
| 字体 | 沿用本地 Manrope / Noto Sans SC；正文 14–15，次级 12–13，重要状态不低于 12 DIP |
| 大数字 | 时钟/专注 40–48 DIP；固定数字布局，避免倒计时抖动 |
| 间距 | 4/8/12/16/24/32 DIP；内容不贴边，文字与控件有共同对齐线 |
| 圆角 | 紧凑/悬停近半高；大型展开约 48–64 DIP；内容面约 12–16 DIP |
| 状态 | 普通、悬停、按压、键盘焦点、禁用、加载、失败都使用同一套组件状态 |

胶囊继续采用原生区域；外侧阴影可能被区域裁掉，优先做好表面内的明暗和细边。工作台继续使用 Windows 系统边框/圆角。增加真正的透明合成或模糊必须另做渲染实验，不能默认通过添加透明度获得图中的材质。

### 3.2 三态与尺寸适配

| 形态 | 建议尺寸起点 | 内容职责 |
|---|---|---|
| 紧凑 | 约 280×44 DIP | 一个主活动；至多一个次活动提示 |
| 悬停 | 约 500×72 DIP | 当前活动的摘要与 2–3 个快捷动作 |
| 音乐展开 | 宽屏约 1000×280 DIP | 音乐、天气、时间/控制 |
| 专注展开 | 约 680×232 DIP | 当前阶段、圆环、暂停/结束、关联任务 |
| AI 状态展开 | 约 460×160 DIP | 当前状态、停止、打开工作台、待确认入口 |
| 提醒 | 约 420–560 DIP 宽、内容驱动高度 | 标题、时间、完成/稍后；正文有限行数 |

以上都是 DIP。以当前显示器可用工作区减去边距得到可用宽高，不把 1920 物理像素当成 1920 DIP。

- 可用宽度 ≥960 DIP：音乐/天气/快捷控制三栏。
- 760–959 DIP：音乐主栏和窄辅助栏；天气缩为一行摘要。
- 480–759 DIP：音乐单栏；天气与更多控制从明确入口打开。
- 更窄区域：封面和文字上下排布，次要信息进入工作台；不压缩整幅界面使文字变小。
- 工作台按工作区限制最小尺寸；窄窗口收窄导航，内容纵向滚动。当前固定 `MinWidth=900`、`MinHeight=600` 需要适配高缩放屏幕。

### 3.3 动效

保留现有 `IslandMotion` 和可取消意图。宽高、圆角、封面矩形、内容透明度同帧更新；中途反向保留当前位置和速度。文字不随整个面板非等比缩放。

延续当前 140ms 进入/150ms 离开意图；主形变从约 180–240ms 的体感起点调校，内容约 140–180ms。这不是强制所有弹簧固定时长。默认高阻尼；减少动画时直接落定或极短淡入。

同一首歌的进度更新不重播入场。背景天气返回不重建正在编辑的页面。全屏隐藏、长时间睡眠、显示器变化撤销过时过渡。动画结束停止逐帧订阅。

### 3.4 声纹、歌词与播放器边界

SMTC 的媒体信息不能直接当作音频采样。图 1 的真实声纹需要独立音频采样模块：可选 WASAPI loopback，在可见且播放时采样、后台计算频带、有限频率绘制；隐藏/暂停时释放或停采。先提供默认音频输出的可视化，若与当前播放器不是同一来源，界面应说明其含义。无采样时显示静态播放标识，不伪造频谱。[微软 loopback 文档](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording)

歌词先完善本地 LRC，再添加可选择/纠正/缓存的自动匹配。收藏、播放列表、歌词来源、随机/循环等功能都要有实际播放器或服务能力；不能因为图片上出现图标就提供无效按钮。

## 4. 功能分期

| 阶段 | 可交付结果 | 完成门槛 |
|---|---|---|
| M1：视觉与可靠性 | 三个主要样板达到同一视觉标准；窄屏适配；修复已确认的数据问题 | 真实窗口截图、双语、键盘、连续操作；数据错误有回归用例 |
| M2：日常使用闭环 | 活动调度、专注恢复、提醒、任务/笔记持久化 | 重启/睡眠/时钟改变后不丢失、不重复；活动不打断用户操作 |
| M3：文件与系统控制 | 文件卡片/拖出/丢失恢复；音频设备；外观、快捷键；可选亮度/电池/性能 | 能力检测、失败反馈、设备插拔、多显示器与低开销 |
| M4：AI 做具体事情 | 创建待办/提醒、保存笔记、开始专注的可编辑提议与执行结果 | 复用相同业务服务；取消零写入；重复点击不重复创建；提示词同步 |
| M5：产品化 | 数据迁移、备份、安装/升级/卸载、崩溃恢复、文档 | 旧数据可回退；长期测试和发布证据完整 |
| 后续探索 | 外部 Agent 状态、剪贴板、日历源、插件接口 | 每项先证明真实需求与稳定接口，再单独立项 |

### M1 的具体顺序

1. 统一主题资源、表面边缘、常用控件与文字层级；先做一个小改动可实窗比较的材质切片。详见 `docs/superpowers/plans/2026-10-04-native-material-foundation.md`。
2. 修复天气三项已复现问题：缓存到期后不自动刷新；换城失败仍显示旧城天气；较早请求覆盖较晚选择。增加请求代次/取消、绑定城市的结果与明确更新时间；只刷新可见或需要的数据。
3. 完成展开布局宽度分级，以及工作台卡片内容行高。覆盖长曲名、无封面、英文、无天气与失败提示。
4. 打磨音乐封面/歌词/进度和专注圆环；同一活动的图标、标签、动作保持一致。
5. AI 补普通 JSON 回应兼容、响应/事件/历史边界；保持流式停止/重试和关闭窗口后的状态完整。上限可先参照旧客户端已有约束，再用实际内容验证。
6. 音频默认设备更换后重新绑定服务；不让扬声器切到耳机后滑杆失效。

这里的天气与 AI 普通 JSON 问题已在本会话的隔离探针复现；默认音频设备项来自静态代码审查，实施前补设备切换复现。此轮规划没有修改这些产品代码。

### M2：活动调度和可靠存储

形态、当前活动和用户操作保护分开。以 OpenNook 的队列/合并机制为参考，在 `Lingyu.Core` 实现小型活动调度器；不先引入通用插件容器。[活动队列源码](https://github.com/twinkling-reality/opennook/blob/3e97de90a2d569f39f1cf7221d0d4bd1f1ca748c/Sources/NookComponents/Activities/NookActivityQueue.swift)

建议规则：

1. 拖文件、拖滑杆、打开菜单、编辑/确认操作期间锁定当前交互；新事件进入待处理。
2. 明确手动选择的主活动保留；其他持续活动以次级指示出现。
3. 到期提醒与专注完成优先于普通系统反馈；优先级只影响等待项，不无限中断已经呈现的内容。
4. 连续音量变化合并为一个事件；同一提醒使用稳定的发生 ID；AI token 只更新状态，不创建新活动。
5. 临时活动结束恢复先前活动；原活动已结束时重新选择有效活动，避免恢复过时快照。
6. 待处理有数量和过期上限；重要提醒存入历史，隐藏或勿扰不意味着丢失。

存储先服务真实需求：设置可继续使用小型版本化 JSON；专注会话、提醒、任务/笔记、AI 历史逐步进入 SQLite 事务与迁移。凭据继续 DPAPI。数据库写入不占用 UI 线程；备份和恢复要能实测。历史列表分页/虚拟化，不把整个历史一次性渲染。

专注保存会话 ID、当前阶段、开始/截止时间、暂停剩余时间和完成记录。提醒保存发生 ID、截止时间、状态与重复规则；睡眠恢复与重启后统一重新计算。应用退出期间的到期行为必须定义并实测，不能把常驻计时器描述为退出后仍有效。

### M3：完整但克制的工具集

- 文件：保存引用，显示文件类型/缩略图/大小；打开、定位、拖出、移除引用。移动/删除后的源文件显示“找不到”，允许重新定位。外部拖放先支持实际本地路径；虚拟邮件附件另做导入流程。文件页的“移除”不删除源文件。
- 系统音频：默认设备变化、输出选择、静音和可选每应用混音；设备不支持或离线时呈现真实状态。
- 外观：主题色、密度、位置、显示器、贴顶/留缝、减少动画；用少量有边界的选项保持视觉一致性。
- 快捷键：显示/隐藏、展开/收起、打开工作台、启动专注；注册失败明确指出冲突，不静默替换用户已有快捷键。
- 亮度：内置屏和外接屏分别探测；DDC/CI 是否可用依设备能力决定。失败时显示不可用或打开系统设置。[微软显示器配置说明](https://learn.microsoft.com/en-us/windows/win32/monitor/using-the-high-level-monitor-configuration-functions)
- CPU/RAM：仅在对应面板可见或被固定时低频采样；不能为一张偶尔打开的卡片常驻高频轮询。
- 跨应用通知：先做独立原型，验证包身份/manifest、权限与撤销。默认只展示用户启用的来源，不修改系统通知全局开关。自身提醒优先交付。[微软通知监听说明](https://learn.microsoft.com/en-us/windows/apps/develop/notifications/app-notifications/notification-listener)

摄像头/麦克风使用状态、蓝牙电量、第三方通知回复均需另做 Windows 能力调查；其他平台展示过这些功能，不等于 Windows 可以统一准确支持。

### M4：AI 的产品上限

第一批动作限定为四个现有业务方向：创建待办、创建提醒、保存笔记、开始专注。流程是“理解输入 → 可编辑提议 → 用户确认 → 调用业务服务 → 显示真实结果”；失败和取消有明确状态。同一提议使用稳定 ID 防止重复提交。

例如“明天下午三点提醒我交方案”：展示解析后的具体日期、时区与标题，修改后确认；服务成功保存后才在岛上反馈。模型输出文本不能充当完成凭据。

长期可以加入用户主动开启的外部 Agent 状态桥接：运行中、等待输入、完成、跳回对应窗口。先做状态监测；跨工具批准命令涉及不同协议，单独设计，不能根据读取到的日志自动批准。参考 Notchi、Vibe Island 和 Open Agent Island 的产品组织，不沿用它们全部的工具权限与进程模型。

## 5. 保持可维护性的边界

```text
Lingyu.App                    WPF 视图、页面状态、呈现与用户输入
        ↓
Lingyu.Core                   活动调度、计时/提醒、业务动作、数据契约
        ↑
Lingyu.Platform.Windows       媒体、音频、通知、快捷键、窗口/显示器能力
```

`App` 负责组合服务；`Core` 不依赖 WPF、Win32 或 Dispatcher。平台事件整理成带来源与版本的快照，再由 UI 消费。现有 `SessionModel` 在实际新增模块时逐步拆出对应的模型/服务；避免仅增加 partial 文件而仍让一个对象承担所有职责。

按需要增加 `ActivityCoordinator`、专注会话存储、提醒调度和音频设备服务。能复用现有 `IslandMotion`、`IslandState`、`MediaSnapshot`、`LrcDocument` 的部分直接复用。视觉实验不同时引入 WinUI/Skia/WebView 多套渲染栈。

所有新可见文案进入原生双语目录。能力变化同步 `native/Lingyu.Core/NativePrompt.cs` 与对应验证；`src/main/ai/systemPrompt.ts` 继续只描述旧客户端实际能力。不能提前把规划中的提醒、Agent 或通知接管写成可用能力。

## 6. 验收证据

| 维度 | 必须看到的证据 |

| 视觉 | 三个样板的真实窗口截图；浅/深桌面背景；100/125/150/200% DPI；中英文与长内容 |

| 资源 | 预热后空闲、音乐、声纹、工作台、AI 流式各自测量；关闭工作台 100 次与长期运行趋势 |

延续项目已有拟定门槛：常驻 Private Bytes ≤120 MiB、工作台 ≤240 MiB、空闲平均整机 CPU ≤0.5%；60Hz 动画回调 P95 目标 ≤20ms，高刷新目标单独实测。它们是预算，不是本轮测量结论。实际屏幕呈现与 WPF 回调时间分开报告；禁止用强制 GC 或工作集裁剪制造数字。外部模型进程单列。
